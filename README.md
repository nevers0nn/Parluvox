# Parluvox

HR-инструмент для технических собеседований: HR озвучивает вопрос кандидату,
приложение вживую распознаёт речь, показывает вопрос на языке оригинала и в
переводе на русский, и генерирует **эталонный ответ** (тоже на двух языках),
чтобы HR — часто не эксперт в предметной области — мог сравнить его с тем,
что говорит кандидат.

Инструмент открыт: работает со своего экрана HR, ничего не скрывает и не
записывает кандидата тайно. Начать сессию нельзя, пока не отмечено, что
кандидат уведомлён (см. `ConsentGate`).

Одна кнопка на всё интервью — **▶ Начать собеседование**. По нажатию
одновременно открываются два канала:

- **🎙 Ты** — микрофон HR (`getUserMedia`).
- **🎧 Собеседник** — системный звук (`getDisplayMedia` с
  `systemAudio: "include"`), нужен, когда звонок идёт в наушниках и обычный
  микрофон не ловит голос собеседника. Работает независимо от того, в каком
  приложении идёт звонок (Zoom/Meet/Teams/Discord), потому что захватывается
  системный аудио-драйвер целиком, а не конкретное приложение. Chromium-only;
  в диалоге "Поделиться экраном" нужно выбрать **"Весь экран"** и включить
  **"Также поделиться системным звуком"**. Если пользователь откажется от
  этого шага, сессия не падает — просто продолжает слушать только микрофон
  (с явным предупреждением в UI), деградация graceful.

Оба канала транскрибируются непрерывно и независимо. Каждая законченная
фраза, распознанная как вопрос (эвристика — финальный транскрипт длиннее
8 символов и заканчивается на "?", см. `isQuestionShaped` в `pipeline.ts`),
автоматически уходит в `buildQaRecord` и превращается в карточку — без
дополнительных нажатий кнопок посреди интервью. Известное ограничение этой
эвристики: вопрос, который Deepgram не завершил вопросительным знаком (редко,
но случается на неровной аудиодорожке), не будет подхвачен автоматически —
ручного оверрайда сейчас нет.

## Архитектура

```
packages/
  server/   Node.js + TypeScript. WebSocket-сессия, STT (Deepgram), LLM (pluggable), файловое хранилище истории.
  web/      React + Vite. Захват микрофона HR, live-транскрипт, карточки "вопрос/ответ".
  desktop/  Electron-обвязка над web (опционально, см. "Запуск через Electron").
```

Функциональное ядро отделено от side-effect'ов:

- `packages/server/src/core/sessionState.ts` — чистый редьюсер состояния сессии,
  без I/O. Покрыт тестами без единого мока.
- `packages/server/src/core/pipeline.ts` — оркестрация перевода и генерации
  эталонного ответа поверх интерфейса `LlmProvider` (тесты используют фейковую
  реализацию — это заглушка на границе системы, а не мок собственного кода).
- `packages/server/src/llm/`, `src/stt/` — все внешние вызовы (LLM, STT) и
  `src/repository/` (хранилище) изолированы за интерфейсами.

## Выбор LLM — оставлен вам

В коде **нет дефолтного провайдера**. `LLM_PROVIDER` обязателен
(`openai` или `anthropic`), сервер не стартует без него. Обе реализации
(`src/llm/openaiProvider.ts`, `src/llm/anthropicProvider.ts`) написаны через
прямые HTTP-вызовы (без SDK) и реализуют один и тот же интерфейс `LlmProvider`,
так что добавить третьего провайдера — это один новый файл + одна строчка
в `factory.ts`.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить LLM_PROVIDER, соответствующий *_API_KEY, DEEPGRAM_API_KEY

npm run dev:server      # http://localhost:8787, WS-эндпоинт /session
npm run dev:web          # http://localhost:5173, проксирует /session на сервер
npm run test:server      # тесты чистого ядра
```

## Запуск через Electron

Обычный запуск в Chrome (см. выше) требует диалога "Поделиться экраном" для
захвата звука собеседника (`getDisplayMedia` + `systemAudio: "include"`) —
это чисто локальный захват, ничего никуда не транслируется, но диалог всё
равно всплывает при каждом запуске и не даёт скрыть окно приложения от чужого
захвата экрана (если HR сам когда-либо шарит свой экран в другом контексте).

`packages/desktop` — тонкая Electron-обвязка над тем же `packages/web` без
изменения его кода, которая закрывает оба момента:

- `session.setDisplayMediaRequestHandler` в главном процессе тихо отдаёт
  системный звук (`audio: "loopback"`) без нативного диалога.
- `win.setContentProtection(true)` исключает окно из захвата другими
  приложениями — `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` на
  Windows 10 версии 2004+ (на более старых Windows окно вместо этого будет
  видно чёрным прямоугольником), `NSWindowSharingType.none` на macOS.

```bash
npm run dev:server       # сначала поднять сервер и web как обычно
npm run dev:web
npm run dev:desktop      # затем открыть тот же web в Electron-окне
```

`packages/desktop` подключается к уже запущенному `dev:web` по адресу из
`PARLUVOX_WEB_URL` (по умолчанию `http://localhost:5173`) — это не
production-сборка, а окно для одного и того же дев-сервера.

## Portable-сборка (один .exe, чтобы отдать другу)

```bash
npm run package:desktop
```

Соберёт `packages/server` и `packages/web`, скопирует их в
`packages/desktop/vendor` вместе с рантайм-зависимостями сервера (`ws`,
`undici` — единственные, у них самих зависимостей нет) и упакует всё через
`electron-builder` в `packages/desktop/release/Parluvox-<версия>-portable.exe`.
Это самодостаточный файл: сервер (Node/WS/LLM/STT) и собранный `web/dist`
запускаются внутри самого приложения как один процесс
(`utilityProcess.fork`, статику отдаёт сам сервер — см. `WEB_DIST_DIR` в
`http/server.ts`), второй Node.js на компьютере друга не нужен.

Ключи друг настраивает так же, как вы — копирует `.env.example` в `.env`,
вписывает свои `LLM_PROVIDER`/`*_API_KEY`/`DEEPGRAM_API_KEY` — и кладёт этот
`.env` **рядом с `.exe`** (portable-сборка Electron даёт переменную
`PORTABLE_EXECUTABLE_DIR`, указывающую именно туда, а не на временную папку
распаковки — `.env` подхватится оттуда тем же `loadDotEnv`, что и в dev).
Ваши ключи в exe не попадают — `.env` в `.gitignore` и никогда не копируется
в vendor/release.

Если у друга что-то не запустилось — лог главного процесса лежит в
`%APPDATA%\Parluvox\desktop-debug.log` (путь к серверу, его stdout/stderr,
ошибки ожидания старта).

Собран и вручную прогнан весь путь (asar пришлось отключить —
`utilityProcess.fork` не умеет спавнить процесс из файла внутри `app.asar`,
только с реального диска). Не сделано: код-подпись exe (Windows/SmartScreen
предупредит про неизвестного издателя), иконка приложения, автообновления,
сборка под macOS/Linux.

## Что осознанно не сделано (решения за вами / за компанией)

- **Хранилище** — сейчас JSONL-файлы на диск (`data/<sessionId>.jsonl`) за
  интерфейсом `QaRepository`. Для прод-использования — замена на
  Postgres/аналог, это отдельное архитектурное решение (объём данных,
  retention policy, бэкапы).
- **Аутентификация HR** — не реализована. Внутренний инструмент компании
  обычно живёт за SSO/VPN; конкретный механизм — решение ИТ/безопасности.
- **Data retention / 152-ФЗ** — транскрипты и сгенерированные ответы
  сохраняются бессрочно локально. Нужна политика хранения и, вероятно,
  юридическое согласование формы уведомления кандидата (сейчас это просто
  чекбокс в UI, ничего no более).
- **Определение языка вопроса** — сейчас грубая эвристика (кириллица → `ru`,
  иначе `en`). Для мультиязычных интервью (не ru/en) стоит заменить на вызов
  LLM/отдельного language-detection сервиса.
- **STT-провайдер** — захардкожен Deepgram (как в статье-источнике), но тоже
  за интерфейсом `SttProvider` — при необходимости меняется так же, как LLM.
- **Упаковка Electron-приложения** — `packages/desktop` сейчас только для
  локального запуска (`electron .` поверх `dev:web`), без сборки
  инсталлятора (`electron-builder`/`electron-forge`), автообновлений и
  production-загрузки собранного `web/dist`. Для раздачи HR-командой это
  отдельный шаг.
